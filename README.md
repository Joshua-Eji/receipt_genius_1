# Receipt Genius

A Flutter application that lets small and medium businesses issue, sign and store digital receipts from a phone.

Built as my undergraduate research project at the University of Nigeria, Nsukka - *Design and Implementation of a Receipt Generation Application for SMEs*.

## What it does

Nigerian SMEs mostly issue handwritten receipts. They are slow to write, easy to lose, and nobody has a record once the customer walks off with the only copy. Receipt Genius replaces that with something a shop owner can run from the phone already in their pocket.

**Two account types.** Businesses register and issue receipts; customers register and hold the receipts they have been issued. The app routes to a different home screen depending on which you are.

**Receipts as real PDFs**, rendered on device and viewable in the app.

**Handwritten signatures**, captured on the touchscreen and embedded in the receipt - the part that makes a digital receipt feel like the paper one it replaces.

**Delivery by email**, so the customer gets a copy without needing the app.

**Cloud storage and sync** through Firebase, so a receipt survives a lost or replaced phone.

**Light and dark themes**, and layouts that scale across screen sizes.

## Built with

Framework: Flutter, Dart

Auth: Firebase Auth, Firebase App Check

Data: Cloud Firestore, Firebase Storage, SharedPreferences

Documents: pdf, syncfusion_flutter_pdfviewer

Signatures: flutter_signature_pad, syncfusion_flutter_signaturepad

State and routing: Provider, GetX

Also: image_picker, file_picker, flutter_email_sender, permission_handler, flutter_screenutil

## Structure

lib/auth - authentication gate and login/register switching

lib/pages - landing, account selection, user and business flows, receipt generation, receipt database, settings

lib/components - shared buttons, text fields, app bar, drawer

lib/theme - light and dark theme definitions, theme provider

## Running it

Run flutter pub get, then flutter run.

Firebase configuration lives in lib/firebase_options.dart and is generated by the FlutterFire CLI. You will need your own Firebase project to run this against - create one, then run flutterfire configure.

## What I would do differently

The receipt data model lives in the page files rather than in its own layer, which made every new feature touch UI code that should not have cared. If I rebuilt this, the first thing I would do is pull receipts, businesses and customers into proper models with a repository between them and the widgets.

This was also written before I had worked on anything with real users, and it shows in the error handling - most failure paths assume the network is there and the write succeeded.
